# SPEC / schema / skill proposals from batch p3_13 (not applied)

No sim configs written (no dielectric traveling-wave device with grade A or B), so no sims/SPEC.md proposals.

- V_pi/2 conventions (thiele2022): bulk Ti:LN devices quote V_pi/2 for a Senarmont min-to-max swing (phase modulator), a full-transfer switching voltage (directional coupler) and a mode-conversion voltage (polarisation converter). None maps to `vpi_convention`; Vpi columns were left empty. Propose a `switch_voltage_v` / `v_half_pi_v` column or a convention value `half_pi_derived`, plus `device_class` values `switch` and `polarisation_converter` (rows now use `other`).
- Resonator bandwidth provenance (kari2025, hou2024, larocque2024): `bw3db_ghz` mixes an EO S21 crossing, a photon-lifetime limit and an optical linewidth. Propose `bw_kind` (eo_s21 | photon_lifetime_estimate | optical_linewidth) so views can filter; hou2024 left bw3db empty because only the optical linewidth was reported.
- Per-cavity values on one device (larocque2024: two cavities with different Q 6.6e4 / 7.4e4 and tuning 9.2 / 8.7 pm/V): one row carries cavity 1, cavity 2 in notes. Propose either a per-cavity convention (row per cavity) or min/max columns for q_loaded and tuning.
- `device_class` for resonant IQ/coherent devices: `iq_mzm` used for larocque2024 (Michelson, two PhC cavities) and kari2025 MZIs with resonators in the arms, following geravand2025-b; the name is a misnomer for non-MZ interferometers. Propose a `resonant` tag convention or a class `iq`.
- Transducer papers (holzgrafe2020, multani2025) have metrics with no columns: on-chip photon transduction efficiency, g0/2pi, cooperativity, conversion bandwidth (optical-linewidth limited), operating temperature. They were entered as papers.csv-only. If cavity-EO transduction is in atlas scope, propose `eta_transduction`, `g0_hz`, `transduction_bw_mhz`, and an rf_center_frequency_ghz column.
- Table typography errors in a source (thiele2022 Table 1 gap unit "mm"): skill could say whether the evidence note plus assumed unit is acceptable or the cell must stay empty; here entered as um with a flagged note.
- Skill / batch contract: the task statement said no crossref.json exists for this batch, but three of six (larocque2024, holzgrafe2020, hou2024) had one; identity then follows Crossref (year, authors) while the numbers follow the cached arXiv version. A rule for preprint-vs-Crossref author mismatches (hou2024: preprint single author, Crossref six) is needed; here Crossref authors were used and flagged.
- `year` vs paper_id for arXiv-first papers whose journal year differs (hou2024: id 2024, Crossref 2023): the skill should state that paper_id is stable and year follows the verified record.
- `discovered_via` vocabulary in the schema does not include the discovery tokens carried by the batch CSV (web_search, author_group_followup, continuation_2026_10_02); copied as written.
- Metrics with an ambiguous electrode-length reference (kari2025: "modulation region 80 um" not tied to a (W, L) device): `length_mm` left empty; a note field convention for "stated generically, not per device" would help.
