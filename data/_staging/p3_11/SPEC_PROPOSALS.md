## Schema / skill (devices.csv)
- No column for analog linearity: feng2022 reports two-tone SFDR (120.04 dB Hz^(4/5) at 1 GHz, 114.54 at 5 GHz; reference MZI 102.31 dB Hz^(2/3)) as its headline. Stored as text in `modulation_format`. Proposal: `sfdr_db_hz_exp` plus `sfdr_exponent` (2/3 or 4/5) and `sfdr_freq_ghz`, or a documented free-text convention.
- `device_class` has no value for a ring-assisted MZI (feng2022): entered as `mzm` with tags `ring_assisted_mzi;resonant`. `ring` would misrepresent it; proposal: allow `mzm` + a `resonator_assisted` tag convention in the schema comment.
- Frequency-dependent Vpi (gao2024, dual-arm delay-line phase modulator): Vpi is about 3 V only near 12, 16, 22 and 26 GHz and diverges in between; `vpi_rf_v` / `vpi_rf_freq_ghz` hold one point and the others go to notes. Proposal: allow several rows per RF operating point (convention d already allows it) or a list column; also recognize `vpi_rf_v` with `at_ghz` as a sim target (already proposed by p3_01).
- `bw3db_reference` has no value for "referenced to the lowest frequency that could be measured" (nelan2022: sidebands only from 3 GHz because the RF source was unlevel below that). Entered `unspecified` with a note.
- `vpi_convention` for single phase modulators with two electrode pairs in series (gao2024): `per_arm_phase_shifter` implies an MZM arm; entered `unspecified`.
- `il_fiber_to_fiber_db` versus `il_onchip_db` when the paper says only "insertion loss" with spot-size converters at both facets (gao2024): entered as fiber-to-fiber with a note; a schema value "unspecified" for the loss definition would avoid the guess.

## sims (nelan2022, gao2024)
- Segmented / T-segment slow-wave electrodes (nelan2022a, not configured): the loaded and unloaded cross-sections depend on stem, base and head roles that the paper shows only as a top-view schematic. `line.loading.type: periodic_t_rail` expects a T-rail with a floating-bar pair; a segmented CPW with stems attached to the electrode needs a documented mapping (which cut is "loaded") before configs can be written reliably.
- Two waveguides in one cross-section: both configs keep both gaps in the electrostatic domain and solve the optical mode on the right arm (same as chen2022); there is still no first-class way to state per-arm overlap factors for push-pull versus single-arm Vpi.
- UV15 index-matching fluid over the electrodes (nelan2022): no region material fits a fluid of unknown RF permittivity that fills only the electrode gaps; the config models air and says so in the n_rf target source.
- Omitted RF permittivities: both configs follow the churaev2023 convention (omit unstated eps_r and Pockels values, list under `missing`), which makes them not runnable; an explicit incomplete-draft status (already proposed by p1_01 and p3_01) would let the app load them.
