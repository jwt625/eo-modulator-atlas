# Schema / skill proposals from batch p3_17 (not applied)

No sim configs written (graphene, ITO and carrier-effect devices), so no sims/SPEC.md proposals.

- `eo_material` has no value for transparent conducting oxides (ITO in gui2022 and lotkov2024): `other` used. Propose `ito` or `transparent_conducting_oxide`. Same carrier-effect mechanism gap as p3_05 and p3_08: an `eo_effect` enum (pockels, plasma_dispersion, carrier_accumulation, franz_keldysh, pauli_blocking, ...) would separate graphene Pauli-blocking, ITO accumulation and silicon plasma dispersion.
- `integration` has no value for transferred 2D material (semi-dry or wet-transferred CVD graphene on a foundry waveguide) or for deposited oxide films on a finished photonic chip: `other` used for graphene, `monolithic` for ITO (paper wording). Propose `transfer_2d` and `deposited_film`.
- Graphene and ITO capacitor devices that are EAMs have no meaningful `drive`/`vpi_convention`; `drive = single_ended` used for EAMs (as steckler2025 in p3_05); an explicit `not_applicable` value or documented empty-means-n/a would help.
- Modulation efficiency in dB/V (giambra2021: 0.25 to 1 dB/V; tiberi2025: 0.037 and 0.01 dB/V/um; heidari2022: 5.2 dB/V) is the headline metric of EAM papers and has no column; kept in notes. Propose `mod_eff_db_per_v` (with `mod_eff_db_per_v_um` or the length used) and `energy` columns next to `extinction_ratio_db`.
- Theory-only and simulation-only papers (navarro2026, gui2022): per-row `*_basis` columns cover only vpi, bandwidth and loss. A paper-level `result_basis` (measured / simulated / mixed) in papers.csv would let views filter simulated devices without reading evidence files. A `design_study` tag was used in the free-tag vocabulary.
- Several rows in one paper differ only by temperature and single-arm vs push-pull (navarro2026: six Table 1 rows). Convention (d) allows rows per operating point; a `scheme` or `operating_point` text column would make such families sortable. Push-pull rows halve the length at constant VpiL, so `vpi_convention` plus length alone does not show the relation.
- No column for gate-dielectric thickness or material in capacitor-type devices (tiberi2025 20 vs 40 nm Al2O3; navarro2026 HfO2 vs Al2O3; gui2022 15 nm Al2O3); stored in `epitaxy_or_stack` text. Propose `gate_dielectric` and `gate_dielectric_nm`.
- No columns for per-device capacitance basis vs resistance (RC) or active area: tiberi2025 active area (22 and 13 um2), gui2022 25 Ohm, lotkov2024 1140 Ohm are in notes. Propose `series_resistance_ohm` and `active_area_um2`.
- Authors' own Table-I-style values with no trace (tiberi2025 20 nm device: 17 GHz, 20 Gbit/s) cannot be labelled with the current `basis` enum; `measured` used with an "unverified" evidence note. Propose a basis value `reported_unverified` (or `author_table`).
- Bandwidth reference: S21 plots normalized to a low-frequency plateau (tiberi2025, heidari2022, lotkov2024) fit `bw3db_reference = unspecified`; the schema could add `plateau` or a `bw3db_reference_note` column. Extrapolated 3 dB crossing at the instrument limit (tiberi2025 67 GHz) is covered by convention (c) only partly: the paper says "extrapolated", not "around".
- Skill: for papers that cache the journal-typeset article under an arXiv id (giambra2021 p.1 shows ACS Nano footer and CC-BY notice), state whether license may be filled from the paper's own notice (convention (k) allows it) or must stay empty per the batch rule; this batch followed the batch rule.
- Skill: when the same paper names a fabrication process only by citing a reference (tiberi2025 Ref. [103] with a CORNERSTONE URL), say whether `foundry_or_fab` may be filled; left empty here.
- Skill wording: BATCH_INSTRUCTIONS text says verified_on 2026-10-01, the task for this batch said 2026-10-02 (used).

## Audit follow-up (2026-10-03)
- Superseded: the giambra2021 bullet above. The audit showed that BATCH_INSTRUCTIONS ("Rights and privacy") and convention (k) allow the license from the paper's own notice or crossref.json, so license, redistribution, published_on and source_type were filled for giambra2021; the cached file is the ACS Nano typeset article served as arXiv v2, and `url`/`arxiv_id` stay the arXiv v2 file. Open question for the coordinator: whether `url` should then point to the DOI (as p3_07 lu2020 does).
- `drive` was emptied for all EAM rows (giambra2021, tiberi2025, heidari2022, lotkov2024); `single_ended` meant "one MZM arm driven", which is not applicable. An explicit `not_applicable` enum value would let views tell "not applicable" from "not reported". gui2022-b and navarro2026 keep `drive` with `derived` evidence entries.
- tiberi2025-b Table-I-only cells (17 GHz, 20 Gbit/s, 20 GBd) now carry basis `author_estimate` as the closest existing label; `reported_unverified` (see the proposal above) is still preferred.
- Convention (k) evidence for paper-level license/published_on: the validator rejects evidence entries with a non-device field (see p3_16 follow-up); the giambra2021 page-1 notice is quoted in `papers.csv` notes instead.
- lotkov2024 `il_onchip_db`: the authors label 14.6 dB "on-chip IL" and 5.7/6.3 dB "insertion loss of the modulator"; the column name `il_onchip_db` cannot carry that ambiguity. The row keeps 5.7 dB with the scope documented as undefined.
